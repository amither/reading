# 阅读打卡 PWA 设计文档

日期：2026-11-23

## 1. 目标

给孩子用的语文、英语朗读打卡 PWA。纯本地运行，没有后端。每次打卡必须录音，读完提交。以自然周（7 天）为周期统计打卡天数。排行榜由程序每天自动构造，让孩子觉得同学也在打卡。

## 2. 已确认的决策

| 主题 | 决策 |
|---|---|
| 任务 | 语文、英语两个独立任务，各有各的周期、日历、排行榜 |
| 周期 | 自然周，周一到周日，自动衔接，无需设置 |
| 补卡 | 每任务每周最多 3 次，只能补本周已过去且未打卡的日期，补卡也要录音 |
| 排行榜范围 | 只看当前周期，每周一重新生成 |
| 技术栈 | Vite + Vue 3 + TypeScript + vite-plugin-pwa，Vue Router hash 模式 |
| 托管 | GitHub Pages，GitHub Actions 自动构建发布 |
| 应用名称 | 「阅读打卡」 |
| 虚拟同学 | 使用同学名单中的全部同学；头像本地生成，约 40% 用默认灰色人像 |
| 同学名单 | 不进仓库；设置页导入本地 JSON；未导入时用内置 30 个随机姓名 |
| 本人信息 | 设置页填写姓名、年级、班级 |
| 备份 | 导出和导入 `.zip`，含记录、设置和全部录音 |
| 任务文案 | 内置默认值，设置里可编辑标题、署名、说明；不做示范音视频 |
| 排名方式 | 密集排名（1、2、3 连续），同天数名次相同 |
| 实时感 | 做：虚拟同学当天是否已打卡由种子决定，天数一天内略有变化 |

## 3. 页面

底部两个 Tab：首页、设置。

| 页面 | 内容 |
|---|---|
| 首页 | 两张任务卡片，显示本周进度「已进行 X/7 天」和今日是否已打卡 |
| 任务详情 | 标题、署名、说明（可展开）、补卡规则文字、排行榜入口、本周日历格、底部主按钮 |
| 录音打卡页 | 录音、计时、暂停/继续、停止、试听、重录、提交 |
| 打卡记录 | 头像、姓名、年级班级、「已坚持 N 天」、提交时间、音频播放条 |
| 排行榜 | 顶部「X/7 天」，金银铜奖牌加数字名次，本人高亮 |
| 设置 | 个人信息、任务文案编辑、导入/清除同学名单、导出/导入备份、检查并更新、版本号 |

主按钮状态：打卡 / 已打卡 / 补卡（选中过去的缺卡日期时）。周期自动衔接，不出现「打卡已结束」。

日历格：已打卡显示蓝色勾，未打卡显示灰色勾，附「查看详情>」。右上角徽章显示「已坚持 N 天」。

## 4. 代码分层

- `core/period`：自然周计算、日期工具，纯函数
- `core/checkin`：打卡、补卡、坚持天数、补卡额度规则，纯函数
- `core/leaderboard`：按日期种子生成虚拟同学与排名，纯函数
- `storage`：IndexedDB 读写（记录、录音、设置、同学名单），备份导出与导入
- `services/recorder`：MediaRecorder 封装
- `services/pwa`：Service Worker 注册、检查更新、持久化存储申请
- `views`、`components`：页面与界面组件

## 5. 数据模型（IndexedDB）

| 存储 | 键 | 内容 |
|---|---|---|
| `checkins` | `taskId + date` | `taskId`（chinese/english）、`date`（YYYY-MM-DD，本地时区）、`submittedAt`、`isMakeup`、`durationSec`、`audioId` |
| `audios` | `audioId` | 录音 Blob、mimeType、时长 |
| `settings` | 固定键 | 姓名、年级、班级、两个任务的标题/署名/说明、同学名单 |
| `meta` | 固定键 | 是否已提示添加到主屏幕、名单导入时间 |

一个任务一天只有一条记录。补卡时 `date` 为被补的那天，`submittedAt` 为真实提交时间，并标记 `isMakeup`。

## 6. 核心规则

### 打卡与补卡
- 今日打卡：只能给当天打卡，每天每任务一次。
- 补卡：只能补本周内已过去且未打卡的日期；不能补未来，也不能补上一周。
- 补卡额度：每周每任务 3 次，等于本周 `isMakeup=true` 的记录数，不单独存储。用完后入口置灰，提示「本周补卡次数已用完」。
- 坚持天数：本周已打卡的天数（补卡计入），不要求连续。
- 跨天：以设备本地时间为准；录音中途跨过 0 点，按录音开始那天计。
- 删除：不提供单条删除，只在设置里整体清空。

### 排行榜生成
- 种子：`日期 + taskId` 哈希后输入 mulberry32。同一天内结果一致，每天变化，两个任务榜单不同。
- 人数：名单中的全部同学；未导入名单时用内置 30 个随机姓名。
- 天数：设截至今天已过天数为 `n`（周一为 1）。每人天数在 `[max(0, n-2), n]` 内按偏向高值的分布抽取，保证不会出现超过 `n` 的天数。
- 实时感：每个虚拟同学当天是否已打卡由种子决定。下午之前未打卡者，天数少算一天，晚上补上。
- 本人：用真实坚持天数加入并一起排序。
- 排名：密集排名；同天数名次相同。
- 同分顺序：按种子打乱，本人在同分中的位置也由种子决定。
- 头像：按姓名哈希选颜色，渲染首字母色块；约 40% 用默认灰色人像；同一人头像固定。

## 7. PWA 与更新

- manifest：`name` 与 `short_name` 均为「阅读打卡」，`display: standalone`，主题色取绿色和蓝色。
- 缓存：`registerType: 'prompt'`，预缓存全部静态资源，离线可用。
- 「检查并更新」：
  1. 调用 `registration.update()` 查新版本。
  2. 有新版本：提示「发现新版本，立即更新？」，确认后 `updateServiceWorker(true)` 并刷新。
  3. 无新版本：提示「已是最新版本」。
  4. 网络失败：提示「检查失败，请检查网络」。
  5. 设置页显示构建时注入的版本号。
- 更新只替换程序文件，不动 IndexedDB 数据。

### Logo 与图标
- 形象：小孩捧着书阅读的卡通图案，绿色和蓝色为主色，圆角方块底。
- 源文件为一份 SVG，保留在仓库。
- 导出：192 与 512 的 PNG、maskable 版本（主体缩进到中心 80%）、180×180 的 `apple-touch-icon`（iOS 添加到主屏幕读取它）。
- 生成后先给用户看效果图，确认后再使用。

## 8. 录音

- 权限：第一次点「开始录音」才请求麦克风；被拒绝时显示引导文字。
- 格式：用 `MediaRecorder.isTypeSupported` 依次探测 `audio/mp4`、`audio/webm;codecs=opus`、`audio/webm`，优先 mp4（iOS Safari 仅支持它）。mimeType 随录音保存。
- 流程：开始、暂停/继续、停止，可试听、重录，满意后提交。提交前不写入数据库；退出页面时确认。
- 限制：最短 3 秒才能提交；最长 30 分钟，到时自动停止。
- 保活：录音时请求 Wake Lock（不支持则跳过）；切走 App 时提示可能中断。
- 播放：`URL.createObjectURL`，页面销毁时释放。

## 9. 备份与恢复

- 导出：fflate 打包成 `.zip`，`data.json` 存记录与设置，录音为独立文件；文件名带日期。优先用 `navigator.share`，不支持时回退为下载。
- 导入：先校验格式与版本号，再让用户选「覆盖」或「合并」。覆盖会清空现有数据；合并时同任务同一天保留提交时间较新的一条。
- 同学名单不进备份，单独导入。
- 首次启动调用 `navigator.storage.persist()`，并提示添加到主屏幕。

## 10. 部署

- `.github/workflows/deploy.yml`：推送到 `main` 后安装、构建、发布到 Pages。
- `base` 从环境变量读取仓库名；本地开发用 `/`。
- 路由用 hash 模式，子路径下刷新不会 404。

## 11. 测试与验证

- Vitest 覆盖 `core/` 全部纯函数：周期边界（周日到周一）、补卡额度、排行榜确定性、天数上限、密集排名。
- iPhone 真机验证：录音、息屏、添加到主屏幕、离线打开、更新流程。

## 12. 不在范围内

后端服务、账号体系、多孩子切换、单条删除、往期排行榜、示范音视频、点赞和评论。
